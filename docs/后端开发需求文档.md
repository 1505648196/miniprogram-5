## 1. 数据模型规范（后端必读）

### 1.1 `baozi_posts` 字段体系

**通用字段**（所有分类共有）：
```
_id, data_type, _openid, userid, province, province_code, city, city_code,
district, district_code, address, latitude, longitude, raw_text, phone,
phone_masked, phone_normalized, contact, username, image, credit, published_at,
source, needs_review, approved, sec_status, sec_label, tags, views, claimed, claimed_at,
coord_system, _ai_enriched, created_at, updated_at
```

**分类枚举 `data_type`（9 类）**：
```
recruit 招工 / jobseek 求职 / transfer 店铺转让 / want_shop 求店 /
equip_sell 设备出售 / equip_buy 设备求购 / carpool_car 车找人 /
carpool_person 人找车 / other 其他
```

**分类专项字段**：
| data_type | 字段 | 说明 |
|---|---|---|
| recruit | `role`(岗位), `role_id`(1-14), `salary`(给价) | 0=面议 |
| jobseek | `role`, `role_id`(1-14), `salary`(=期望，冗余), `salary_expect`, `salary_note`, `availability`(到岗), `service_area`(可服务地区), `want_terms[]` | `salary` 必须=`salary_expect` |
| transfer | `role`(店铺类型), `role_id`(1-5), `price`(转让费), `monthly_rent`(月租), `area_sqm`(面积), `daily_revenue`(日营业额), `has_equipment`(带设备), `terms[]` | |
| want_shop | `role`, `role_id`(1-5), `price`(预算), `rent_max`(租金上限), `area_min`(面积下限), `want_terms[]` | |
| equip_sell/equip_buy | `price`(售价/预算), `cond`(成色 0-10) | 10=全新 |
| carpool_car/carpool_person | `from_place`, `to_place`, `depart_time`, `depart_deadline`, `seats` | 无价格 |
| other | 无价格字段 | |

**师傅类型 role_id（1-14）**：大师傅/短期顶班/夫妻工/售卖员/学徒工/小笼包师傅/饼类师傅/油炸类师傅/中工/生煎类师傅/全能面点大师/二把手/工厂/其他类型。
**店铺类型 role_id（1-5）**：品牌店/自营店/摆摊车/学校/工厂。

**关键字段语义**：
| 字段 | 含义 |
|---|---|
| `source` | `"user"`(用户发布) / `"import_legacy"`(老数据迁移约 2900 条，`_openid=""` 平台代发) |
| `approved` | **审核权威字段**：`true`=已通过/可展示，`false`=待审核/未通过。恒等于 `!needs_review` |
| `needs_review` | 反向冗余字段（`true`=待审，`false`=通过），与 `approved` 始终同步，保留用于老数据兜底 |
| `reviewed` | 预留字段（`adminAuth.audit` 审核通过时写 `true`），非权威，仅作"人工审核过"标记 |
| `sec_status` | 内容安全检测结果 `pass`/`risky`/`reject` |
| `views` | 浏览量（原子自增） |
| `claimed` | 老数据是否已被用户认领 |
| `phone_normalized` | 纯 11 位手机号，用于老数据归属匹配 |
| `coord_system` | 坐标系（老数据 `bd09`，新数据未标） |
| `_ai_enriched` | AI 补全的字段名数组 |

### 2.2 审核工作台 —— ✅ 已完成

**现状**：
- 审核权威字段为 `approved`（`true`=已通过/可展示，`false`=待审核），`needs_review` 为其反向冗余（恒等于 `!approved`）。
- `adminAuth.audit` 已实现：`_id, note` → 置 `needs_review=false, approved=true, reviewed=true, reviewed_at, review_note`。
- 审核通过后**自动推站内通知**给发帖人（写 `baozi_messages`，`type=review`；老数据 `_openid=""` 无归属则跳过）。后台 shadcn-vue-admin 用 Switch 双向切换审核状态（开=通过调 `audit`，关=待审调 `update` 置 `approved=false`）。
- 新帖发布 `publishPost` 默认 `needs_review=false`/`approved=true`（自动放行），仅当微信内容安全检测非 `pass` 才改 `approved=false`（待复核）。

**接口**（`adminAuth`）：
| action | 入参 | 返回 |
|---|---|---|
| `audit` | `_id, note` | `{ success, notified }`（置 `needs_review:false, approved:true, reviewed:true, reviewed_at, review_note`；`notified`=是否已推站内通知） |
| `update` | `_id, data{needs_review:true}` | `{ success, updated }`（后台「驳回/置待审」用，`sanitizeFields` 会同步 `approved=false`） |

**⚠️ 待确认的产品决策**：
- 当前是微信内容安全**自动放行**（`sec_status=pass` 直接发布）。如果业务要求"所有帖子人工审核后才上线"，需改 `publishPost` 默认 `approved=false`（`needs_review=true`）。这是产品决策，需确认。

**验收**：后台能拉待审核列表（`approved=false`）、审核通过后发帖人收到通知、Switch 可双向切换审核状态。

## 5. 多端身份体系 —— ⬜ 未写（需预留，重点）

> 规划要支持 H5（服务号）、iOS、安卓、鸿蒙 App，都会绑定微信。这是**后端必须预留并重点设计的模块**。

### 5.1 核心原则

**用 `unionid` 做跨端用户主键**（前提：小程序、公众号、App 都绑定到**同一个微信开放平台账号**）。

| 标识 | 作用 |
|---|---|
| `unionid` | 跨端同一微信用户的唯一主键 |
| `openid` | 单端标识（每个应用不同，不能跨端） |
| `uid` | 对外唯一 ID（自增/雪花，供展示和引用） |

### 5.2 字段设计（`baozi_users` 已预留字段）
```
unionid       — 跨端主键（需建唯一索引）
openid_wxapp  — 小程序 openid
openid_mp     — 服务号/公众号 openid
openid_web    — 网页 openid
openid_app    — App(iOS/安卓/鸿蒙) openid  ✅ 已补齐
uid           — 对外唯一ID（原子自增）
```

> ✅ `baozi_users` 的 `createUser` 已补齐 `openid_app` 字段。

### 5.3 登录逻辑改造（`getOrCreateUser`）—— 🔶 部分完成

**已实现**（`getOrCreateUser`）：
```
登录时拿到 openid + unionid（微信开放平台绑定后可拿）
→ 优先用 unionid 查用户
  ├─ 查到 → 回填当前端 openid 到对应字段（多端绑定同一账号）
  └─ 查不到 → 退回按 openid 查 → 新建（写 unionid + 当前端 openid）
→ 兜底：拿不到 unionid 时，用手机号做跨端打通（老数据已有 phone_normalized）
```
- 封禁校验：`status=banned` 直接拒绝登录。

**待完成**：
- ⬜ 服务号 H5 / App 登录入口（需新增 `h5Login` 云函数，用 code 换 openid/unionid），小程序端已就绪。

### 5.4 uid 生成改造 —— ✅ 已完成

已把 `uid: count.total + 1` 改为**原子自增**：独立 `baozi_counters` 集合，`{ name:"user_uid", seq:0 }`，每次乐观锁自增取号，避免并发重复。

### 5.5 老数据兼容
- 老用户（`baozi_users` 已存在）`unionid=""`，需在下次登录时用 openid 查到后回填 unionid。
- 老帖子（`import_legacy`）靠 `phone_normalized` 认领，与 unionid 无关，保持现状。

### 5.6 微信开放平台前提（需确认）
- ⬜ 确认小程序、服务号、App 是否绑定到**同一个微信开放平台账号**。未绑定则拿不到一致的 unionid，多端打通无法实现。
