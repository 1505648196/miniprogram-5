# 包子一哥传媒 · 小程序页面重设计说明书

> **本文档的用途**：交给负责「重新设计一套页面」的 AI 阅读，使其在不了解项目历史的情况下，也能准确理解业务、页面结构、数据契约与硬约束，从而产出一套可落地的新 UI。
>
> **使用方式**：现有页面代码**先保留不动**，新设计产出后再替换。本文档只描述「现状与约束」，不规定新视觉风格——视觉风格由设计方发挥。
>
> 配套文档：`docs/API-云函数对接文档.md`（接口字段权威）、`docs/项目说明-给后台开发.md`（后台侧）。

## 1. 一句话定位

**包子（早餐/面点）行业的信息平台小程序**。核心是「**同城信息撮合**」：老板招工、师傅求职、店铺转让、求店、二手设备买卖、顺风车搭车、以及「包友群 / 包友圈商家 / 包子快讯」三类社区内容。用户免费发布、按城市与条件筛选、看中后**付费或开通会员查看对方完整手机号**。

- **形态**：微信小程序（无 H5、无 App）
- **技术**：微信原生小程序 + **TDesign 组件库（tdesign-miniprogram 1.9.x）** + 腾讯云开发 CloudBase
- **小程序标题**：包子一哥传媒
- **目标用户**：包子铺老板、面点师傅（大师傅/中工/学徒等）、餐饮设备商、早餐创业者。**用户以中年蓝领为主，操作习惯偏「大字、少层级、信息直给」，设计需照顾可读性与点击热区。**
- **不做的事**：不做私信聊天（平台明确不提供用户间 IM）；不做用户自主注册（微信 openid 无感登录）

## 2. 全局设计约束（必读，违反会导致功能失效）

### 2.1 组件库
**必须使用 TDesign（tdesign-miniprogram）组件，禁止手写原生 HTML 元素或自造组件。**

- 组件路径：`tdesign-miniprogram/xxx/xxx`（在页面 `.json` 的 `usingComponents` 注册）
- 样式定制一律通过 **TDesign CSS 变量**（如 `--td-button-primary-bg-color`）覆盖，**不要手写 CSS 去改组件内部结构**
- 已在用的组件（可放心使用）：`t-search` `t-grid` `t-grid-item` `t-tabs` `t-tab-panel` `t-tab-bar` `t-tab-bar-item` `t-tag` `t-button` `t-cell` `t-cell-group` `t-input` `t-textarea` `t-picker` `t-upload` `t-cascader` `t-dropdown-menu` `t-dropdown-item` `t-sticky` `t-popup` `t-action-sheet` `t-dialog` `t-skeleton` `t-empty` `t-loading` `t-icon` `t-image` `t-swiper` `t-checkbox` `t-checkbox-group` `t-avatar` `t-toast` `t-chat-sender`

### 2.2 品牌色（现状，可重新设计但需全局统一）
- **主色 = 品牌黄 `#FFE60A`**：导航栏背景、页面顶部 Header、搜索框胶囊底色
- 主文字/描边：`#1A1A1A`
- 页面背景：`#F5F5F5` / `#F6F6F6`
- **业务类型色（9 类信息各自的识别色，全站统一，重设计时建议保留语义）**：

| 类型 | 色值 | 浅底 |
|---|---|---|
| 招工 / 车找人 | `#597EF7` | `#F0F5FF` |
| 求职 | `#9254DE` | `#F9F0FF` |
| 店铺转让 | `#FF7A45` | `#FFF1E8` |
| 求店 | `#36CFC9` | `#E6FFFB` |
| 设备出售 | `#FA8C16` | `#FFF7E6` |
| 设备求购 | `#73D13D` | `#F6FFED` |
| 其他 | `#8C8C8C` | `#FAFAFA` |

- **信用等级色（4 级）**：1 优秀 `#FF7A45` / 2 极好 `#36CFC9` / 3 良好 `#597EF7` / 4 一般 `#8C8C8C`
- 会员金：`#D4AF37` / `#FFD666` / `#C98A1F`

### 2.3 导航结构
- **底部导航 5 项**（全站一致）：`首页` / `附近` / `发布` / `消息`（带未读红点）/ `我的`
- 实现方式有两套（**非微信原生 tabBar**）：
  1. TDesign `t-tab-bar` 内嵌（首页、我的、我的发布）
  2. 公共组件 `comp-tabbar`（各频道页、附近、消息页）
- 点击非当前项用 `wx.reLaunch` 清栈；「发布」项统一跳「我的发布」页
- 图标用 TDesign icon 名（`home` / `location` / `add-circle` / `chat` / `user`）

### 2.4 交互一致性约定
- **骨架屏**：统一 `t-skeleton`（`animation="gradient"`）；双列流用 `row-col` 模拟图文错落
- **空态**：统一 `t-empty`，按场景给不同 icon（`search` / `notification` / `heart` / `wallet` / `info-circle` / `time`）
- **加载更多**：局部 `t-loading`（`theme="circular"`）+ 底部「— 没有更多了 —」
- **吸顶**：统一 `t-sticky`
- **筛选条**：`t-dropdown-menu` + `t-dropdown-item`（`show-overlay=false`）
- **弹层**：`t-popup`（底部弹 / 居中弹）
- **删除类操作**：`t-dialog` 二次确认
- **操作中**：`wx.showLoading({ mask: true })`，结果 `wx.showToast`

### 2.5 数据与性能约束（重设计时不能破坏）
- **详情页零二次请求**：列表页已把帖子快照写入本地缓存 `detail_pool`，详情页优先读缓存。**列表卡片只需要传 `id` 即可跳详情**，不要在卡片里塞完整数据。
- **图片**：上传到云存储得 `fileID`（`cloud://` 开头），展示时 `<image src="{{fileID}}">` 可直接用；但**后台/浏览器展示需要换临时 https 链接**。
- **手机号脱敏是硬规则**：所有展示文本（标题、正文、地址、联系方式）都必须过 `utils/privacy.js` 的 `maskText()`，把手机号变成 `138****5678`。完整号码**只允许存内存、绝不渲染到界面**。
- **地区筛选用行政区划 code**（`city_code`），不用城市名（避免「深圳」vs「深圳市」歧义）。

## 4. 核心页面的信息架构（重点参考）

> 以下是重设计时最需要关注的核心页，列出「现状从上到下的区块顺序」与「每块承载的信息」。新设计可调整视觉与排布，但**信息项不应缺失**。

### 4.1 首页 `demo`（流量入口，最重要的门面）

现状区块顺序：

1. **顶部 Header**（品牌黄底）：Logo「包子一哥」+ 圆角搜索框（占位文案「搜索 招聘，求职，转让，设备」）
2. **金刚位 5 入口**（一行 5 格，图标 + 名称）：
   - 招聘求职（含招工+求职）/ 转让求店（含转让+求店）/ 二手设备（含出售+求购）/ 顺风车 / 其他
   - 图标为远程图片，加载失败回退 emoji
3. **广告轮播位**：`t-swiper`，自动播放 5 秒。**无广告时整块不渲染**（不留空白）
4. **热门推荐卡片组**（白底卡容器）：区头「热门推荐 + 查看全部」；下方左大卡「今日头条」（红色 tag + 插画 + 标题 + 价格 + 「查看详情」CTA）+ 右上 VIP 会员卡 + 右下 包友群卡。**均为广告系统驱动，无广告不渲染**
5. **包友圈商家横滚**：区头「包友圈商家 + 全部 >」；横向滚动 3 张商家小卡（图 + 名）+ 1 张「更多商家」卡；加载中显示骨架（4 个）
6. **顶部 Tab（吸顶）**：`最新消息` / `附近消息`（触发定位）/ `转让求店` / `求职招聘`，支持左右滑切换
7. **双列瀑布流**：加载中=骨架；空=提示；有数据=双列卡片
   - **卡片结构**：图片（右上角叠加「置顶徽章 + 类型徽章」；无图则标签条置顶）→ 标题（≤30字截断）→ 标签（≤3 个 `t-tag`）→ 发布人（user 图标 + 信用标签）→ 地区·时间 → 价格 + 「查看 ›」
   - 卡片支持 `isTop` 置顶态特殊样式（`goods-card-top`）
8. **底部 TabBar**：5 项，「消息」带未读红点，「我的」在会员时切换成金色 VIP 图标
9. **右下角悬浮按钮**：分享按钮（始终有）+「管理员 AI」金色圆形按钮（**仅管理员可见**）
10. **全局弹窗广告**：`t-popup` 居中，支持频控（每天一次/仅一次/每 N 天等），右上角关闭

### 4.2 帖子详情 `detail`（转化核心页）

现状区块顺序：

1. **顶部信息卡**：类型徽章（带类型色）+ 标题
2. **顶部卡片广告**（`position=top_card`，无则不渲染）
3. **封面图**（有图才渲染）
4. **关键信息卡**：**按 `data_type` 动态渲染不同字段行**（见下表）
5. **详情描述**（正文，已脱敏）
6. **发布信息**：发布时间 / 浏览量 / 发布用户 / 信用等级
7. **底部固定操作区**：
   - **本人帖子**：「编辑」+「删除」
   - **非本人**：提示文案（含「举报」文字链）+「收藏」+「查看联系方式 / 免费拨打电话」（会员时文案不同）
8. 悬浮按钮：分享（始终）+「转发到朋友圈」（仅管理员）
9. 删除确认 `t-dialog`；管理员转发编辑弹窗

**关键信息卡按类型的字段差异（9 类）**：

| data_type | 展示字段 |
|---|---|
| `recruit` 招工 | 岗位（role）、薪资（salary 元/月）、区域、联系电话、详细地址、标签条件 |
| `jobseek` 求职 | 师傅类型、期望薪资（salary_expect，前缀「期望」）、到岗方式（availability）、可服务地区（service_area）、诉求（want_terms） |
| `transfer` 店铺转让 | 店铺类型、转让费（price）、月租（monthly_rent）、面积（area_sqm）、日营业额（daily_revenue）、是否带设备（has_equipment）、条件（terms） |
| `want_shop` 求店 | 期望店铺类型、预算（price）、租金上限（rent_max）、面积下限（area_min）、诉求 |
| `equip_sell` 设备出售 | 设备售价（price）、成色（cond 0-10） |
| `equip_buy` 设备求购 | 预算（price）、要求成色（cond） |
| `carpool_car` / `carpool_person` | 出发地→目的地、出发时间、最晚出发、可乘人数（**无价格**） |
| `other` 其他 | 仅通用字段（区域、电话、地址、描述） |

### 4.3 招聘求职频道 `recruit`（筛选逻辑最复杂的频道）

现状区块顺序：

1. 顶部 Header（品牌黄 + 搜索）
2. 广告区块
3. **师傅类型金刚位**：5 列网格，默认露出 4 个 + 第 5 格「更多类型」（点击展开剩余 10 个，按钮变「收起」）；共 **14 类师傅**
4. **吸顶筛选条**（`t-dropdown-menu`）：① 师傅类型（下拉单选列表）② 区域（常用城市快捷标签 + 「查看完整省市区」级联选择）③ 工资（输入最低薪资 + 清空/确定）
5. **信息类别多选卡**：招聘 / 求职 / 会员（三张卡，前两者真正筛选数据，会员是占位入口）
6. **双列瀑布流**
7. 区域级联选择弹层 `t-cascader`（打开时会临时隐藏筛选条避免遮挡）
8. 底部 TabBar

**14 类师傅类型**（`role_id` 1-14，稳定映射，筛选走 role_id 而非中文名）：
大师傅 / 短期顶班 / 夫妻工 / 售卖员 / 学徒工 / 小笼包师傅 / 饼类师傅 / 油炸类师傅 / 中工 / 生煎类师傅 / 全能面点大师 / 二把手 / 工厂 / 其他类型

> **注意**：代码中有一个 `wx:if="{{false}}"` 的注释残留在筛选条外层 `<block>` 上——**这是历史遗留，筛选条实际是显示的**。重设计时直接按「显示」处理。

### 4.4 我的 `mine`（个人中心）

现状区块顺序：

1. **顶部品牌黄 Header**：头像 + 昵称（会员加皇冠图标）+ 信用标签 + 右「帮助与客服」「设置」
2. **会员横幅**：未开通=「会员开通 / 专属标识·曝光更多 / 免费发布·免费查看 / 立即开通」；已开通=「会员 / 有效期至 xxx / 续费」
3. **4 列统计**：收藏数 / 浏览历史 / 我的发布 / 其他（点击跳对应页）

5. **公告条**：一条滚动公告
6. **通用组**：意见反馈 / 清除浏览缓存 / 关于我们

### 4.5 三个发布页（表单）

| 页面 | 适用类型 | 表单区块 |
|---|---|---|
| `publish`（通用） | 转让/求店/设备出售/设备求购/求职/其他 | 类型选择(grid) → 地区与价格 → [设备成色] → [求职到岗] → [诉求条件] → 联系方式(手机/联系人/**地图选点**) → 描述 → 图片(1张) → 提交 |
| `publish_recruit`（招工） | 招工 | 招什么师傅(grid) → 薪资/地区/地图选点 → 联系方式 → 描述 → 图片 → **置顶推广（付费选项）** → 提交 → 发布后「推荐帖子」弹窗 |
| `publish_carpool`（顺风车） | 车找人/人找车 | 类型选择 → 路线与时间(出发地/目的地/出发时间/最晚出发/可乘人数) → 所在地区 → 联系方式 → 描述 → 图片 → 提交 |

**通用硬规则**：
- **「详细地址」为必填**，必须通过 `wx.chooseLocation` 地图选点获取，**同时保存 `latitude`/`longitude`**
- 手机号必填且校验 11 位
- 提交走云函数 `publishPost`；编辑态走 `managePost.update`（管理员走 `adminAuth.update`）
- 点「提交」时会**同步请求订阅消息授权**（审核结果通知），这是正常流程，不要移除

## 5. 业务规则（设计时需正确表达）

### 5.1 九类信息与其专属字段

| data_type | 中文名 | 所属板块 | 价格字段 | 专项字段 |
|---|---|---|---|---|
| `recruit` | 招工 | 招聘求职 | `salary`（给价，元/月） | `role`/`role_id` |
| `jobseek` | 求职 | 招聘求职 | `salary_expect`（期望）+ `salary`（冗余=期望） | `availability`、`service_area`、`want_terms[]`、`salary_note` |
| `transfer` | 店铺转让 | 转让求店 | `price`（转让费） | `monthly_rent`、`area_sqm`、`daily_revenue`、`has_equipment`、`terms[]` |
| `want_shop` | 求店 | 转让求店 | `price`（预算） | `rent_max`、`area_min`、`want_terms[]` |
| `equip_sell` | 设备出售 | 二手设备 | `price` | `cond`（成色 0-10） |
| `equip_buy` | 设备求购 | 二手设备 | `price` | `cond` |
| `carpool_car` | 车找人 | 顺风车 | **无价格** | `from_place`、`to_place`、`depart_time`、`depart_deadline`、`seats` |
| `carpool_person` | 人找车 | 顺风车 | **无价格** | 同上 |
| `other` | 其他 | 其他 | 无 | 无 |

**通用字段**：`_openid`、`province/province_code/city/city_code/district/district_code`、`address`、`latitude`/`longitude`、`raw_text`（原文）、`phone`、`phone_masked`、`contact`、`username`、`image`、`credit`、`published_at`、`source`、`needs_review`、`approved`、`tags[]`、`views`

### 5.2 价格展示规则（易错点）
- 招工 / 求职 → `${salary} 元/月`；求职前缀加「**期望**」
- 转让 / 求店 / 设备 → `${price} 元`；**≥10000 显示为「x万」**
- 顺风车 → 显示 `出发地 → 目的地`，**不显示价格**
- 其他 → 有价格才显示，否则「面议」

### 5.3 用户体系
- **无感登录**：微信 `openid` 自动识别，无注册流程
- 用户表 `baozi_users` 关键字段：`openid_wxapp`、`username`、`avatar`、`phone`/`phone_masked`/`phone_verified`、`membership`(normal/vip)、`membership_expire_at`、`credit_score`（默认 100）、`role`(user/merchant/admin)、`status`(active/banned)
- **绑定手机号会「认领」历史老帖**（按手机号匹配 `import_legacy` 数据）——历史迁移数据约 2900 条，`_openid` 为空
- 封禁用户（`status=banned`）不能登录、不能发布

### 5.4 会员体系
| 档位 | 价格 | 时长 |
|---|---|---|
| 天卡 | 9.9 元 | 1 天 |
| 月卡 | 50 元 | 30 天（标「推荐」） |
| 年卡 | 299 元 | 365 天（标「超值」） |

**权益**：会员专属标识 / 信息优先曝光 / **免费查看并拨打联系电话**。

### 5.5 付费能力与价格（分→元）
| 能力 | 价格 | 说明 |
|---|---|---|
| 付费看电话 | **0.01 元** | 单日最多 20 帖 |
| 擦亮（刷新排序） | **0.5 元** | — |
| 置顶 1 天 | **50 元** | — |
| 置顶 3 天 | **150 元** | — |
| 置顶 7 天 | **350 元** | — |
| 商家入驻（高级版） | **2999 元/年** | — |
| 会员 | 9.9 / 50 / 299 | 见上 |

### 5.6 内容审核流程
1. 用户发布 → 云端做微信内容安全检测（`checkText`）
2. 检测通过 → `approved=true` 直接公开展示
3. 检测不通过 → `approved=false` 进入**待人工审核**（`needs_review=true`）
4. 列表中只展示 `approved=true` 的帖子
5. 审核通过/退回后：发**站内通知**（`type=review`）+ 发**微信订阅消息**（用户需先授权）
6. 「我的发布」页展示状态标签：**审核中 / 已发布**

### 5.7 站内通知三类（`baozi_messages`）
| 类型 | 触发时机 | 受众 |
|---|---|---|
| `global` | 后台推送平台公告 | 全部用户 |
| `review` | 帖子审核结果 / 发布成功 | 指定发帖人 |
| `member` | 会员开通/续费成功 | 指定用户 |

可见规则：`to_openid` 为空（全局）或等于自己。

### 5.8 广告运营位（数据驱动，集合 `ad_slots` + `advertisements`）
- 位置结构：`page`（页面）+ `position`（位置）+ `type`（banner/card/popup）
- 已知位置：首页 `banner`/`card`/`popup`、详情页 `top_card`、各频道页（recruit/turnover/equip/carpool/other/nearby 各有 `banner`+`card`+`popup`）
- **所有广告位在无数据时必须整块不渲染**（不留占位空白），这是硬规则
- 跳转类型：`page`（跳小程序页）/ `post`（跳帖子）/ `url`（外链）/ `none`

### 5.9 举报 / 意见反馈
- **举报入口**：帖子详情页（非本人帖子）底部文字链
- **意见反馈入口**：「我的」页通用组
- 提交内容：类型（举报/反馈）、理由/分类、补充说明（≤500字）、最多 3 张截图、联系方式
- 举报理由：虚假信息 / 电话骚扰 / 垃圾广告 / 涉嫌诈骗 / 内容违规 / 已成交失效 / 其他
- 反馈分类：功能建议 / 使用问题 / 举报投诉 / 内容错误 / 其他

## 6. 可复用的 UI 模式

### 6.1 标准双列信息卡（全站最高频组件）
```
┌─────────────────┐
│  图片（可选）    │ ← 右上角叠加：置顶徽章 + 类型徽章
│                 │    无图时标签条移到卡片顶部
├─────────────────┤
│ 标题（≤30字）    │
│ [标签] [标签]    │ ← ≤3 个
│ 👤 信用标签      │ ← 有信用分才显示
│ 地区 · 时间      │ ← 「深圳 · 今天」
├─────────────────┤
│ 价格        查看 ›│
└─────────────────┘
```
- 价格语义按类型变化（见 5.2）
- 置顶卡片有特殊视觉（`goods-card-top`）
- 瀑布流为**左右两列交替分配**（偶数索引左列、奇数右列）

### 6.2 骨架屏
- 列表页：双列骨架，每卡 = 图块（rect）+ 2 行文字（text），左右高度错落
- 详情页：徽章 → 标题 → 大图 → 多行信息 → 底部按钮

### 6.3 筛选条模式（各频道页通用）
```
[师傅类型 ▾] [区域 ▾] [工资 ▾]   ← t-dropdown-menu，吸顶
```
- 打开时 `show-overlay=false`
- 区域筛选：常用城市快捷 tag（10 个热门城市）+「查看完整省市区」跳级联选择

### 6.4 空态 / 加载态
- 骨架 → 空态（`t-empty`）→ 内容，三态互斥
- 触底加载：局部 loading + 「— 没有更多了 —」

## 8. 给设计 AI 的具体建议

### 8.1 重设计优先级
1. **首页 `demo`** —— 门面，信息密度最高，最值得重做
2. **帖子详情 `detail`** —— 转化核心，9 类动态字段是最大设计难点
3. **三个发布页** —— 表单体验直接影响发布量
4. **频道页（recruit/turnover/equip/carpool）** —— 筛选条 + 双列流，可统一抽象
5. **我的 / 我的发布** —— 功能密度高但结构清晰
6. 其余页面按需

### 8.2 设计时必须保留的信息项
- 卡片：类型徽章、标题、价格、地区时间、发布人/信用（有则显示）
- 详情：类型、所有专项字段、脱敏电话、举报入口、收藏
- 发布：地址必填（地图选点）、手机号必填、订阅授权触发点

### 8.3 可以自由发挥的部分
- 配色体系（保留品牌黄或整体换新，但 9 类业务色建议保留语义可辨识度）
- 卡片圆角、阴影、间距体系
- 金刚位图标风格（现为远程图片 + emoji 回退）
- 头部区域的视觉（现为纯色黄底）
- 筛选条的交互形式（下拉 / 抽屉 / 底部弹层均可）
- 骨架屏、空态的视觉风格

### 8.4 需要特别注意的坑
1. **TDesign 组件限制**：`t-upload` 的 `add` 事件 `e.detail` 直接是数组；`t-grid-item` 的 `bind:click` 的 `e.detail` 是整个 item 对象；`t-action-sheet` 在 grid 模式下只渲染 `t-icon`
2. **`t-cell` 内嵌内容必须用具名 slot**（`slot="note"`/`slot="right-icon"`），默认插槽不显示
3. **手机号脱敏不能省**，否则会有隐私合规风险
4. **广告位空数据不渲染**，不要画成固定占位块
5. **底部导航不是原生 tabBar**，是 TDesign 组件 + `reLaunch` 跳转
6. **图片用 `fileID`**（`cloud://`），不是普通 URL

### 8.5 建议输出形式
为了让后续能顺利落地，建议设计方输出：
1. **设计规范**：色板（含 9 类业务色）、字阶、间距、圆角、阴影
2. **组件规范**：信息卡（有图/无图/置顶三态）、筛选条、空态、骨架屏、按钮层级
3. **页面视觉稿**：按 8.1 的优先级，每个页面含 loading / 空 / 有数据三态
4. **交互说明**：筛选、弹层、跳转的预期行为
