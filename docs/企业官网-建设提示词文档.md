# 包子一哥传媒 · 企业官网建设提示词文档（含 GEO / SEO）

> **本文档用途**：交付给「负责搭建企业官网」的 AI 或前端开发者阅读/直接引用。文档内所有标注为「**提示词**」的段落，均可整段复制粘贴给 AI 使用。
>
> **配套**：`docs/项目说明-给UI设计AI.md`（小程序 UI）、`docs/项目说明-给后台开发.md`（后台）。官网是**独立于小程序**的对外门户，不替代小程序。
>
> **使用方式**：按「第 1 部分（内容与架构）→ 第 2 部分（视觉设计提示词）→ 第 3 部分（GEO/SEO 提示词）→ 第 4 部分（验收清单）」顺序执行。

## 0. 先对齐：这个官网要做成什么

### 0.1 主体定位

| 项 | 内容 |
|---|---|
| 官网主体名称 | **包子一哥传媒** |
| 行业 | 包子 / 早餐 / 面点行业的**信息服务平台** |
| 一句话定位 | 包子行业同城信息撮合平台：招工求职、店铺转让、求店、二手设备、顺风车 |
| 服务对象（受众） | ① 包子铺老板 ② 面点师傅/中工/学徒（中年蓝领为主）③ 餐饮设备商 ④ 早餐创业者 ⑤ 想加盟/想转店的人 |
| 核心产品 | 微信小程序「包查查信息 / 包子一哥传媒」 |
| 官网使命 | ① 让搜索/大模型搜得到、看得懂 ② 承接小程序导流 ③ 建立信任背书 ④ 沉淀行业内容做 SEO/GEO 资产 |
| 官网与小程序关系 | 官网 = **门户 + 内容 + 导流**；小程序 = **实际交易与撮合**。官网上所有行动号召（CTA）最终导向小程序码 / 小程序链接 |

> ⚠️ **重要前提（避免后期返工）**：官网需要**独立域名**（如 `baoziyige.com`）和 ICP 备案。若主域名已备案，官网尽量挂在**主域**或**子域**（`www.` / `info.`），不要用一堆互不相干的域名，会分散 SEO 权重。

### 0.2 官网必须避免的误区

- ❌ 做成「纯品牌展示页 + 一张大图 + 联系我们」——这种站对 SEO/GEO **零价值**。
- ❌ 内容全部用图片承载文字——搜索引擎和 AI 读不到图里的字。
- ❌ 只写「我们很专业」这类空话——**要被 AI 引用，必须有具体、可抽取的事实**（城市、数量、价格区间、流程、常见问题）。
- ✅ 正确姿势：**内容是资产**。每一篇「包子店转让流程」「师傅薪资行情」既是给用户看的，也是给搜索引擎和 AI 吃的。

## 1. 第一部分：官网内容与架构提示词

### 1.1 站点地图（信息架构）

```

│   ├─ /equipment        二手设备（设备出售求购）
│   ├─ /carpool          顺风车
│   └─ /nearby           同城/附近（→ 导向小程序）
├─ 内容中心（SEO 主力，持续产出）
│   ├─ /news             包子快讯（行业资讯列表）
│   ├─ /news/:id         资讯详情
│   ├─ /guide            行业百科/指南（长尾关键词主阵地）

> **提示词 1-0：站点地图生成**
>
> ```
> 为「包子一哥传媒」包子行业信息平台设计企业官网的站点地图（URL 结构）。

> 1. URL 用英文、语义化、短横线分隔（如 /guide/open-shop），不用拼音缩写、不用无意义参数。
> 2. 分为 5 大块：首页、频道功能页、内容中心（资讯/指南/FAQ）、城市落地页、信任页。
> 3. 明确标注哪些页面是「SEO 主力页」（需要长期产出内容的），哪些是「功能页」。
> 4. 输出为树形结构 + 一张表格（URL / 页面名 / 页面职责 / 目标核心关键词）。
> ```

### 1.2 首页结构与文案

**首页区块顺序**（自上而下）：

1. **顶部导航栏**：Logo「包子一哥」+ 主导航（招工求职 / 转让求店 / 二手设备 / 顺风车 / 行业指南 / 资讯）+ 右侧「打开小程序」按钮
2. **首屏 Hero**：主标题 + 副标题 + 双 CTA（「打开小程序」/「查看行业指南」）+ 小程序码
3. **数据背书条**：覆盖城市数 / 信息条数 / 师傅数 / 商家数（**数字要真实、可更新，不能编造**）
4. **核心功能四宫格**：招工求职 / 店铺转让 / 二手设备 / 顺风车（各配一句话说明 + 「进入」）
5. **行业指南精选**（引流到内容中心，SEO 内链）
6. **最新资讯**（引流到 /news）
7. **常见问题 FAQ 精选**（GEO 重点，用可折叠问答组件）
8. **商家入驻引导**（2999 元/年，含权益列表）
9. **底部 Footer**：联系方式、备案号、站点地图（sitemap.html）、隐私政策、友链

> **提示词 1-1：首页文案生成**
>
> ```
> 你是「包子一哥传媒」企业官网的文案策划。这是一个包子（早餐/面点）行业的同城信息服务平台，
> 用户主要是包子铺老板、面点师傅（以中年蓝领为主，习惯直给、讨厌空话）。
>
> 请为官网首页写出文案，要求：
> 1. 主标题（≤14字）：一句话说清"我们帮包子行业的人做什么"，不要喊口号、不要"引领""赋能"这类词。
> 2. 副标题（≤40字）：补充说明，点明"免费发布 / 同城匹配 / 覆盖全国"这类具体价值。
> 3. 四个功能块的标题 + 一句话说明（≤25字）：
>    招工求职 / 店铺转让 / 二手设备 / 顺风车。
> 4. 数据背书条文案：用"覆盖XX个城市 · XX万条信息"这类格式（数字留占位符，如 {{cityCount}}）。
> 5. 商家入驻引导文案（权益 3-5 条，每条≤12字）。
> 6. 底部一句话品牌介绍（≤50字）。
>
> 语气要求：朴实、口语、像同行说话，不用营销黑话。所有文案给出「中文版」即可，不要英文。
> ```

### 1.3 频道功能页结构（模板）

每个频道页（招工/转让/设备/顺风车）统一结构：

1. **面包屑**：首页 > 招工求职
2. **H1 标题**：`包子行业招工求职信息平台`（含核心关键词）
3. **简介段**（150-250 字）：说明这个频道解决什么问题、怎么用、覆盖哪些城市（**含关键词自然分布**）
4. **信息列表预览**：从云端拉取最新的 N 条公开帖子（标题+城市+价格，脱敏后展示），点「查看更多」跳小程序
5. **使用指南**（图文步骤 3 步：注册/发布 → 筛选 → 联系）
6. **常见问题**（3-5 条，折叠问答）
7. **相关指南推荐**（内链到 /guide 下对应文章）
8. **CTA**：打开小程序查看完整信息

> **提示词 1-2：频道页内容生成**
>
> ```
> 为「包子一哥传媒」官网的【招工求职】频道页撰写内容。请输出：
> 1. H1 标题（含"包子行业""招工""求职"等关键词，自然不堆砌）。
> 2. 频道简介（180字左右）：说明这里能查到什么（大师傅、中工、学徒、夫妻工等岗位的招聘与求职信息）、
>    怎么用（免费发布、按城市和薪资筛选、看中后联系对方）、覆盖范围。
> 3. 三步使用指南（每步标题≤8字 + 说明≤30字）。
> 4. 5 条常见问题 + 答案（问答要能被 AI 直接引用，答案用陈述句、含具体信息，
>    例如"包子大师傅月薪一般在6000-12000元，一线城市更高"）。
> 5. 3 条相关指南的内链建议（标题 + 建议URL）。
>
> 禁止编造具体公司名、具体人名。数字用"一般""通常"这类可验证的表述。
> ```

| 2 | 包子店转让流程与避坑指南（含转让费怎么算） | 包子店转让 | 指南 |

**文章结构模板**（每篇统一，便于 AI 抓取）：

```
H1 标题（含核心关键词）
├─ TL;DR 摘要框（100字内，直接回答标题问题）★ GEO 重点
├─ H2 目录（锚点跳转）
├─ H2 正文分块（每块 200-400 字，H3 小标题）
│   └─ 关键数据用 <table> 或 <ul> 呈现（AI 易抽取）
├─ H2 常见问题（Q&A，对应 FAQPage 结构化数据）
├─ H2 结语 + 行动号召（跳小程序）
└─ 相关阅读（内链 3 篇）
```

> **提示词 1-3：深度指南文章生成（核心）**
>
> ```
> 你是包子行业的内容专家，为「包子一哥传媒」官网撰写一篇深度指南文章。
>
> 【文章主题】{{标题，如：开一家包子店需要多少钱？成本明细与预算表}}
> 【目标读者】想开包子店/刚入行的创业者、包子铺老板
> 【目标关键词】{{如：开包子店成本}}
> 【字数】1800-2500 字
>
> 【必须包含的结构】
> 1. 文章开头先给一个「TL;DR 摘要框」（80-120字），用一句话+几个要点直接回答标题问题，
>    让读者和 AI 都能立刻拿到答案。
> 2. H2 分节，每节 200-400 字，H3 小标题。
> 3. 涉及数字的地方（成本、价格、比例）尽量用表格呈现，标注"参考区间"并说明因城市而异。
> 4. 结尾 5 条常见问题 Q&A。
> 5. 结尾给出下一步行动建议（引导打开小程序查看真实信息）。
>
> 【硬性要求】
> - 内容要具体、可操作，禁止空话（"要做好市场调研"这类必须给出怎么做的具体方法）。
> - 数字给区间并说明前提（如"一线城市 vs 三四线城市"），不编造精确到个位的不实数据。
> - 自然融入目标关键词 2-4 次，不要堆砌。
> - 用中文，口语化，面向中年蓝领读者，句子短、少术语。
> - 输出 Markdown 格式。
> ```

### 1.5 FAQ 页（GEO 最关键的单页）

FAQ 页是**被 AI 引用概率最高**的页面，因为它是「问答对」结构，天然匹配大模型的检索逻辑。

> **提示词 1-4：FAQ 库生成**
>
> ```
> 为「包子一哥传媒」包子行业信息平台生成官网 FAQ 页内容，30 条问答。
>
> 【问题来源分类】
> - 平台使用类（怎么发布信息？要不要收费？怎么看电话？会员有什么用？）
> - 招工求职类（找包子师傅去哪里？师傅工资多少？招工要签合同吗？）
> - 转让求店类（店铺转让费怎么定？接手要注意什么？）
> - 设备类（二手设备去哪买？怎么验设备？）
> - 行业经营类（开包子店要多少钱？一天卖多少不亏？）
>
> 【每条问答要求】
> 1. 问题用用户真实口语提问（"包子店转让费一般多少钱？"而不是"转让费定价机制说明"）。
> 2. 答案 50-150 字，第一句直接回答问题（AI 抽取时会优先取首句），后面再补充细节。
> 3. 答案里包含具体、可验证的信息（价格区间、数量、城市差异），不说空话。
> 4. 不编造具体商家名、具体人名。
>
> 【输出格式】Markdown，每组一个 H2 分类，下面用 Q/A 列出。
> 末尾附一份 JSON-LD 的 FAQPage 结构化数据（question/answer 数组）。
> ```

### 1.6 城市落地页（区域 SEO，可选分批）

**做法**：用同一套模板，只替换城市名与数据，批量生成 `/city/北京`、`/city/深圳`…。

> ⚠️ **注意**：批量生成的城市页如果内容高度雷同，会被搜索引擎判定为「低质内容农场」而惩罚。**每个城市页必须有该城市独有内容**（真实信息条数、本地薪资/转让价行情、本地常见问题），数据不足的城市先不做。

> **提示词 1-5：城市落地页生成**
>
> ```
> 生成「包子一哥传媒」官网的城市落地页模板。以 {{城市名，如：东莞}} 为例。
>
> 【页面结构】
> 1. H1：{城市}包子行业信息平台 - 招工求职/店铺转让/二手设备
> 2. 本地概况段（150字）：{城市}包子行业特点、常见业态。
> 3. 本地最新信息（从数据接口拉取该城市公开帖子，展示 6-12 条）。
> 4. 本地行情（该城市大师傅薪资区间、店铺转让价区间——用"参考区间"表述）。
> 5. 本地常见问题（5 条，必须与城市强相关）。
> 6. 内链：相邻城市 / 该城市相关指南。
>
> 【要求】每个城市页至少有 3 个"只属于这个城市"的内容点（本地行情、本地问题、本地案例），
> 防止被判为模板化低质页面。若某城市数据不足，输出"该城市内容建设中"的设计说明。
> ```

## 2. 第二部分：视觉设计提示词

### 2.1 品牌视觉基因（从小程序延续）

| 项 | 值 |
|---|---|
| 品牌主色 | **品牌黄 `#FFE60A`**（头部/主按钮/选中态） |
| 主文字 | `#1A1A1A` |
| 页面背景 | `#FFFFFF` / 浅灰 `#F6F6F6` |
| 强调色 | 招工求职 `#597EF7` / 转让 `#FF7A45` / 设备 `#FA8C16` / 顺风车 `#36CFC9` |

**风格定调**：**明亮、干净、有市井烟火气**。不要科技蓝、不要玻璃拟态、不要大面积渐变。要用**真实场景图**（包子铺、蒸笼、师傅手部特写）而非抽象插画，让中年蓝领用户有亲切感。

### 2.2 响应式要求

| 断点 | 宽度 | 说明 |
|---|---|---|
| 移动端 | ≤ 640px | **优先**（大量用户从微信内打开） |
| 平板 | 641–1024px | 双列 |
| 桌面 | ≥ 1025px | 最大内容宽度 1200px 居中，三列 |

**性能硬指标**：Lighthouse 性能分 ≥ 90；LCP < 2.5s；首屏无布局跳动（CLS < 0.1）。图片一律 WebP + 懒加载 + 标注宽高。

> **提示词 2-1：官网整体视觉设计**
>
> ```
> 为「包子一哥传媒」企业官网设计一套视觉方案（输出设计规范 + 关键页面视觉描述）。
>
> 【品牌】包子行业信息平台，品牌黄 #FFE60A + 黑字 #1A1A1A，白底为主。
> 【受众】包子铺老板、面点师傅，以中年蓝领为主 —— 字要大、层级要少、信息直给、按钮热区要大。
> 【风格】明亮干净、有市井烟火气、信任感。禁止：科技蓝、玻璃拟态、大面积渐变、抽象几何插画。
> 【图片】优先用真实场景（包子铺、蒸笼、师傅工作照），不要空泛的商务图库素材。
>
> 【输出要求】
> 1. 色板：主色/辅色/中性色阶/语义色（成功/警示），标注 HEX。
> 2. 字阶：H1-H6、正文、辅助文字的字号/行高/字重，正文字号偏大（≥16px）。

## 3. 第三部分：GEO / SEO 提示词（重点）

### 3.1 先搞懂：SEO 和 GEO 的区别

| | 传统 SEO | GEO（Generative Engine Optimization，生成式引擎优化） |
|---|---|---|
| 目标 | 在百度/Google 搜索结果里排名靠前 | **被 AI（豆包/元宝/ChatGPT/DeepSeek/Perplexity）在回答中引用** |
| 抓取方式 | 爬虫抓网页 → 索引 → 关键词匹配 | 大模型检索+理解内容 → 综合生成答案 |
| 关键 | 关键词、外链、权重 | **结构清晰、事实具体、问答对、可被抽取** |
| 内容偏好 | 关键词密度、标题优化 | **直接答案、表格数据、明确出处、TL;DR** |

> **核心洞察**：GEO 不是「另一套技术」，而是「让内容更容易被机器理解和引用」。做好了 GEO，SEO 通常也跟着好。

### 3.2 GEO 的六条内容法则

1. **开头就给答案**（TL;DR）——AI 抽取时优先看首段。
2. **用问答结构**——FAQ 是 AI 最爱。
3. **数据用表格/列表**——结构化的信息更易被抽取和引用。
4. **说清「是谁、在哪、什么时候」**——包含实体（城市名、岗位名、价格）和时效（2026 年）。
5. **内容有明确主题边界**——一页只回答一类问题，别大杂烩。
6. **可验证**——给区间和前提，别编精确假数据（被 AI 引用后是灾难）。

### 3.3 技术 SEO 清单（必须全做）

| 项 | 要求 |
|---|---|
| **SSR/SSG** | 内容必须服务端渲染，禁止纯 SPA（客户端渲染搜索引擎抓不到） |
| **title / description** | 每页唯一，含核心关键词，描述 ≤ 80 字 |
| **canonical** | 每页指向自己，防重复内容 |
| **结构化数据** | JSON-LD：Organization、WebSite、BreadcrumbList、FAQPage、Article |
| **sitemap.xml** | 自动生成，提交到百度搜索资源平台 + Google Search Console |
| **robots.txt** | 允许抓取，指向 sitemap；**明确允许 GPTBot / Bytespider / ClaudeBot 等 AI 爬虫**（这是 GEO 的关键，很多人误封） |
| **语义化 HTML** | H1 唯一，H2/H3 层级正确，用 `<article>` `<nav>` `<main>` |
| **图片 alt** | 所有图片有描述性 alt |
| **内链** | 文章间互相链接，形成主题簇 |
| **移动友好** | 响应式，通过 Mobile-Friendly 测试 |
| **HTTPS** | 必须 |
| **页面速度** | Lighthouse ≥ 90 |
| **URL 规范** | 小写、短横线、语义化、无参数 |
| **语言标记** | `<html lang="zh-CN">` |
| **备案** | 国内服务器必须 ICP 备案（否则无法在国内访问/收录） |

## 附：关键概念速查

| 术语 | 含义 |
|---|---|
| **SEO** | 搜索引擎优化，让百度/Google 排名靠前 |
| **GEO** | 生成式引擎优化，让 AI 在回答中引用你 |
| **SSR / SSG** | 服务端渲染 / 静态生成，内容页必须用 |
| **结构化数据 / JSON-LD** | 用代码告诉机器「这页是什么内容」 |
| **TL;DR** | 开头直接给答案的摘要框 |
| **实体一致性** | 各平台公司信息完全一致，AI 才认得出是同一个实体 |

> **一句话总结**：官网 = **门户 + 内容资产**。技术 SEO 决定「能不能被抓到」，内容质量决定「会不会被引用」，实体一致性决定「AI 认不认你」。
